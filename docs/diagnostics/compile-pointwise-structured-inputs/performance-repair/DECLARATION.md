# Frontend repair diagnostic declaration

Declared before collection, 2026-09-15. This is an unscored diagnostic under the
approved Main repair plan. The rejected CUDA score (26.3441 versus baseline 28)
remains a blocker; this experiment cannot replace the canonical gate.

Compare base `2f15b4ce53dc45918ea644a3370257f340747755` and rejected candidate
`5ef07240386593dc4cfaff075fac3ce88d47ab2c`, then one chosen repair if profiling
justifies it. Use a single freshly built candidate release extension and Python
3.12 interpreter rooted in this worktree. Load each frontend in a fresh process
before creating any wrapper, verify public `torch_rs.compile(fn)` selects it,
and record source/import/extension/runtime identities. This is a common-native,
frontend-only comparison, not independently built end-to-end baselines. The base
and rejected sources are immutable Git exports inside this worktree.

Six non-corpus cases, each returning its computed result and current input x:

1. Flat one Tensor: `(x * 0.75 - 1.125).relu()`.
2. Flat two Tensors: `x * 1.25 - y * 0.5`.
3. Flat runtime scalars `(gain, x, bias)`: `(x * gain - bias).relu()`.
4. Flat shape history `(gain, x, bias)`: `x * gain - bias` when
   `x.shape[0] < 128`, otherwise `x * gain + bias`.
5. Structured small: `payload['x'] * payload['gain'] - payload['bias']`.
6. Structured wide: same expression, with 4090 unread Boolean values in an
   additional payload list. This remains below the 4096 input-edge bound.

Inputs have one-dimensional shapes 37, 521 and 2053; x and y use distinct
integer-eighth values generated by local `random.Random(19471)` in case/shape
order, x drawn from [-24,24], y from [-16,16]. Creation and upload precede timing.
For every version and case, keep one wrapper alive through seed calls
`(shape,gain,bias) = (37,.375,.125), (521,.625,.25), (2053,.875,.375),
(37,1.125,.5), (521,.625,.25)`. This includes successful shape history and
finite scalar promotion. Timed/warmup calls cycle the first three states.
One first completed-GPU call is recorded separately as cold; remaining seed
calls and 30 warmup calls are untimed. No per-shape history resets.

Each process runs the cases in listed order. Record 12 warm blocks of 300
calls per supported case. Synchronize immediately before the block, start
perf_counter_ns, call the persistent wrapper and retain every output, synchronize,
then stop timing. The interval includes enqueue, Python list retention and GPU
completion; it excludes creation, profiler hooks, correctness transfer, hashing,
artifact writing and release of retained outputs. Outside each block check all
computed values against independently calculated exact binary-fraction values,
metadata and returned input identity, materializing every retained output.
Keep all raw block durations and report medians, quartiles and min/max; no
best-block selection. The base's structured cases are explicitly unsupported,
not flattened substitutes.

Pre-repair process order is base, rejected, rejected, base. After selecting one
hypothesis, comparison order is rejected, repaired, repaired, rejected, with the
same counts, histories and boundaries. Each phase retains its full receipts and
raw data, including failures and unfavorable results. No automatic timing retry.
Run separate CPU profiles (500 warm calls per case, after identical seeding) on
the rejected frontend to attribute binding/hash costs; profiler timings are
CPU diagnosis, never completed-GPU performance evidence. Use one host thread,
CUDA_VISIBLE_DEVICES=0 and worktree-local caches. Record physical GPU snapshots
before/after processes, actual exit codes, commands, source hashes, dirty status,
release wheel and loaded runtime/library versions. Original-body replay is
forbidden during correctness/seed checks, outside timing.

Choose only a measured useful optimization within direct flat admission, cached
structural BindingSource hashing, or inline root-leaf resolution. If none is
supported by the measurements, report the outcome to Main. Do not change native
numerics, caches/history owners, workloads, timing policy or evaluator tooling.
