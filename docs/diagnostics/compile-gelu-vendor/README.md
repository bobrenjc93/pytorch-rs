# Vendor Erf retry: provider input selection failed

**The prescribed NVCC12.8 invocation did not consume the requested official
CUDA11.8 libdevice.** Broad implementation stopped at the first prerequisite;
no replacement provider was linked or executed on a GPU, and no public GELU
surface was added. Production source still matches accepted main
`60202557b4f110d07777f585e804ab5f55e1ff7b`.

The controlled pair uses one C-linkage device function calling stock `erff`,
CUDA12.8 NVCC12.8.93, `--dont-use-profile`, and `--libdevice-directory`. One run
points to the hash-verified official input; the other points to an empty
worktree-local directory. Both processes exited 0 and generated byte-identical
PTX. Neither complete child file/process trace records a libdevice access.
The generated PTX also contains the newer coefficients seen in the failed
CUDA13 experiment; matching coefficient text alone is not numerical evidence.

This is a failed development provider-generation experiment, not a measurement
of final compiled GELU. Source and tool hashes are authoritative for these
commands; the report's code commit identifies the checkout before uncommitted
experimental changes. Paused private-IR/linker edits and an unexecuted diagnostic
were removed after this failure and supply no implementation or test credit.

The actual internal origin of NVCC's emitted math is not established. The visible
host-only `math_functions.hpp` Erf body is excluded by `__CUDACC__`; it must not
be credited as the source. The active CUDA declaration marks `erff` as a compiler
builtin. The specified profile/directory options were already used. Continuing
needs an explicitly justified generation path that demonstrably consumes the
pinned library; silently changing compilers/providers or transcribing math would
violate the repair contract.

To reproduce, copy the official library into a worktree-local input directory,
verify SHA256 `1fc1bc8d4131d5a59a91fc26f4908886e231f842c9e83ae951979ff3df82bdb5`,
and run from this checkout with a fresh output path:

```bash
python -B docs/diagnostics/compile-gelu-vendor/check_provider.py target/gelu-vendor/input/libdevice.10.bc target/gelu-vendor/selection-rerun
```

The official package URLs/digests are in `official-input.json`; use its library
and packaged LICENSE only, without executing downloaded NVCC11.8. The installed
NVCC12.8 is pinned by the diagnostic. Temporary files, traces and outputs remain
inside this worktree. Generation requires `strace` and the declared host compiler.
These commands were run under Burner's existing CPU/GPU lease; they performed no
GPU work. Runtime/driver numerical compatibility remains untested for this retry.

The earlier [GPU failures](../compile-gelu-stage1/README.md) remain immutable at
commit `934719a`. Their full evaluation measured CUDA performance 33.328 against
34 and rejected the evidence-only tree. That result was not resampled or replaced.
No runtime source changed, so this repair establishes no performance gain and
makes no evaluator or baseline adjustment. It reduces tracked historical bulk
and records the exact provider blocker for independent review.
